# Zombie Event Shop

Темний Next.js-магазин для Minecraft Java 1.20.1 івенту "Зомбі проти людей". Вхід на івент безкоштовний, а набори, ресурси й івент-послуги купуються за внутрішню валюту сайту — талери. Баланс поповнюється через заявку: гравець обирає пакет, оплачує суму й пише свій Minecraft-нік із сайту в коментарі платежу. Видача талерів і куплених предметів зараз ручна через адмін-панель.

Проєкт не використовує офіційні логотипи Minecraft, Mojang або Microsoft. Іконки предметів лежать у `public/minecraft-items` і використовуються тільки як магазинні спрайти.

## Стек

- Frontend: Next.js App Router, React, TypeScript, Tailwind CSS.
- Backend: Next.js API routes.
- DB: Prisma + PostgreSQL, готово для Supabase.
- Auth: email + пароль для гравців, окрема адмін-сесія через HttpOnly cookie.
- Payments: ручні заявки на поповнення талерів, optional Monobank jar/link.
- Deploy: GitHub `main` -> Vercel.

## Запуск

1. Встановіть залежності:

```bash
npm install
```

2. Скопіюйте env і заповніть значення:

```bash
cp .env.example .env
```

Мінімально потрібні:

- `DATABASE_URL` — pooled PostgreSQL connection string.
- `DIRECT_URL` — direct PostgreSQL connection string для Prisma push/migrations.
- `APP_URL` — локально `http://localhost:3000`, на проді домен Vercel.
- `ADMIN_PASSWORD` або `ADMIN_PASSWORDS`.
- `ADMIN_SESSION_SECRET`, `USER_SESSION_SECRET`, `EMAIL_VERIFICATION_SECRET`.

3. Синхронізуйте схему й засійте стартові товари:

```bash
npm run db:push
npm run db:seed
```

Увага: seed робить upsert товарів зі `prisma/seed.ts`, а потім видаляє товари, slug-и яких не входять у seed. На production запускайте його тільки свідомо. Для точкового додавання товару краще використати адмін-панель або API.

4. Запустіть сайт:

```bash
npm run dev
```

Сайт відкриється на `http://localhost:3000`.

## Основні Скрипти

- `npm run dev` — локальний Next.js dev server.
- `npm run build` — Prisma generate + production build.
- `npm run lint` — Next lint.
- `npm run prisma:generate` — оновити Prisma Client.
- `npm run db:push` — застосувати Prisma schema до БД.
- `npm run db:seed` — засіяти/синхронізувати товари й глобальні налаштування.
- `npm run db:studio` — Prisma Studio.

## Env

Головний шаблон: `.env.example`.

Корисні групи змінних:

- Database: `DATABASE_URL`, `DIRECT_URL`.
- App/session: `APP_URL`, `ADMIN_SESSION_SECRET`, `USER_SESSION_SECRET`, `EMAIL_VERIFICATION_SECRET`.
- Admin: `ADMIN_PASSWORD`, `ADMIN_PASSWORDS`, `ADMIN_2FA_REQUIRED`, `ADMIN_2FA_EMAILS`.
- Email: `SMTP_HOST`, `SMTP_PORT`, `SMTP_SECURE`, `SMTP_USER`, `SMTP_PASSWORD`, `SMTP_FROM`.
- Manual top-up: `MANUAL_TOP_UP_PAYMENT_URL`.
- Monobank jar fallback: `MONOBANK_JAR_SEND_ID` або `MONOBANK_JAR_ID`.
- Public event info: `NEXT_PUBLIC_EVENT_START_AT`, `NEXT_PUBLIC_MINECRAFT_SERVER`, `NEXT_PUBLIC_STREAM_URL`, `NEXT_PUBLIC_DISCORD_URL`, `NEXT_PUBLIC_TELEGRAM_URL`, `NEXT_PUBLIC_SUPPORT_EMAIL`.

Якщо SMTP не налаштований локально, код підтвердження реєстрації друкується в консолі dev-сервера.

## Ручне Поповнення Балансу

Гравець відкриває `/top-up`, обирає пакет талерів і натискає "Створити заявку". Сайт створює pending-поповнення, показує точну суму, Minecraft-нік як коментар до платежу й optional кнопку оплати.

Пакети зараз задаються в `src/lib/currency.ts`:

| Пакет | Ціна |
| --- | --- |
| 50 талерів | 25 грн |
| 100 талерів | 50 грн |
| 200 талерів | 100 грн |
| 400 талерів | 200 грн |

Якщо `MANUAL_TOP_UP_PAYMENT_URL` порожній, сайт усе одно створить заявку й покаже суму та коментар. Якщо задано `MONOBANK_JAR_SEND_ID` або `MONOBANK_JAR_ID`, кнопка оплати веде на відповідну банку Monobank.

Адмінський сценарій:

1. Гравець створює заявку на `/top-up`.
2. Гравець оплачує точну суму й пише свій Minecraft-нік у коментарі.
3. Адмін відкриває `/admin`, знаходить гравця за ніком або email.
4. Адмін перевіряє pending-поповнення й натискає "Видати талери".
5. Баланс гравця оновлюється, а заявка стає виданою.

## Адмін-Панель

Адмін-панель доступна напряму на `/admin`; посилання на неї приховане з навігації та футера.

Доступ захищений паролем і, за потреби, одноразовим кодом на пошту. `ADMIN_PASSWORD` працює для одного пароля, `ADMIN_PASSWORDS` дозволяє кілька паролів через кому, крапку з комою або новий рядок.

```env
ADMIN_PASSWORD="надійний-пароль"
ADMIN_PASSWORDS="другий-надійний-пароль; третій-надійний-пароль"
ADMIN_2FA_REQUIRED="true"
ADMIN_2FA_EMAILS="admin@example.com"
ADMIN_SESSION_SECRET="довгий-випадковий-секрет"
USER_SESSION_SECRET="інший-довгий-випадковий-секрет"
```

Після правильного пароля сайт надсилає 6-значний код на `ADMIN_2FA_EMAILS`. Код діє 10 хвилин, має 5 спроб і зберігається тільки у підписаній HttpOnly-cookie.

Функції адмінки:

- перегляд замовлень;
- фільтри `pending`, `paid`, `issued`, `failed`, `cancelled`;
- готові `/give` команди з підставленим Minecraft-ніком;
- позначення замовлень як виданих або скасованих;
- пошук гравців за ніком або email;
- перегляд балансу, поповнень, покупок і руху талерів;
- ручна видача pending-поповнень;
- ручне додавання або списання талерів;
- перемикач статусу стріму;
- додавання, редагування й вимикання товарів.

Покупки доступні 24/7. Перемикач стріму не блокує замовлення, а лише показує адміну, що сервер відкритий для видачі після старту стріму.

## Каталог

Основні категорії:

- Базові набори.
- Набори виживання.
- Бойові набори.
- Суперпредмети.
- Івент-послуги.
- Ресурси окремо.

У розділі ресурсів є вкладки:

- Усі.
- Матеріали.
- Блоки.
- Бій.
- Зброя.
- Інструменти.
- Речі Бога.

Стакувані ресурси зазвичай продаються варіантами `x16`, `x32`, `x64`. Нестакувані предмети продаються наборами `x1`, `x3`, `x6`, якщо для них не задані окремі кількості.

Павутина додана як блоковий ресурс:

- `cobwebs-x16` — 12 талерів.
- `cobwebs-x32` — 22 талери.
- `cobwebs-x64` — 38 талерів.

## Додавання Товарів

Товари можна додавати двома способами:

1. Через `/admin` — найкращий варіант для production.
2. Через `prisma/seed.ts` — зручно для базового каталогу, але seed синхронізує весь список і видаляє slug-и, яких немає в seed.

Команди видачі зберігаються з плейсхолдером `{nickname}`:

```text
/give {nickname} minecraft:cobweb 16
```

Під час перегляду замовлення адмінка підставляє реальний Minecraft-нік гравця.

## Деплой

Production деплоїться через Vercel із GitHub-гілки `main`.

Типовий порядок:

```bash
npm run lint
npx tsc --noEmit
npm run build
git push origin main
```

На Vercel потрібно додати ті самі Environment Variables, що й у `.env.example`, але з production-значеннями. Для Prisma schema changes використовуйте `npm run db:push` проти правильного `DIRECT_URL` або налаштований migration flow.

## Майбутня Автоматична Видача

Зараз видача ручна через адмін-панель і готові команди. Для RCON або окремого Minecraft-плагіна можна додати worker, який бере тільки замовлення зі статусом `pending`, виконує команди, а потім переводить їх у `issued`.
